# SIPL 1.0: синтаксис та семантика

Специфікацію зафіксовано в `grammar/sipl.ebnf`. Це EBNF із `,` для конкатенації, `|` для альтернативи, `{…}` для повторення та `[…]` для необов’язкової частини. Парсер реалізує ці правила методом рекурсивного спуску; EBNF не завантажується під час виконання.

## Відповідність джерелам

Базові конструкції відповідають практикуму, с. 8–9, та посібнику Нікітченка, с. 7–11. Оскільки вихідна БНФ неоднозначна, застосовано уточнення пріоритетів із посібника Нікітченка, с. 9–10: `*`, потім `+`/`-`, порівняння, `¬`, `∨`; послідовність операторів має найнижчий пріоритет. Бінарні арифметичні операції, диз’юнкція та послідовна композиція лівоасоціативні. Гілки `if` і тіло `while` — один оператор; кілька операторів групуються у `begin/end`. Обидві гілки `if` обов’язкові.

Дужки змінюють структуру виразів. Для розрізнення `(X+1)>0` та `(X>0)` парсер спочатку пробує порівняння; якщо воно не підходить, повертається до початку і розбирає умову в дужках. У разі двох помилок показує ту, до якої дійшов далі. Це локальне повернення, а не повторний парсинг усієї програми.

## Лексика

- Ключові слова: `begin end skip if then else while do`, малими літерами.
- Змінні: `[A-Z][A-Z0-9_]*`. Посібник не деталізує всю множину Var; це її явна реалізаційна конкретизація.
- Цілі числа: десяткові цифри з необов’язковим мінусом; від’ємні константи, зокрема `-2`, дозволено. Мінус відділяється як токен, тому `X-1` не залежить від пробілів. `-X` не входить до базової БНФ; слід написати `0-X`.
- Оператори: `:= ; + - * = > ¬ ∨ ( )`.
- Пробіли, табуляції та переведення рядка пропускаються. Файли — UTF-8.
- Коментарі, `/`, `div`, `mod`, `<`, `<=`, `and`, `or`, `not`, `true` як літерал, функції та рекурсія не входять до цієї версії.
- Порожні блоки і `;` перед `end` заборонені, як у початковій БНФ. Для порожньої дії є `skip`.

## Стан і частковість

`State` подано словником `dict[str, int]`, який реалізує скінченне часткове відображення Var ⇀ Int. Початковий словник копіюється, а всі не змінені програмою імена зберігаються. `begin/end` лише групує оператори: локальної області видимості немає.

Звернення до відсутньої змінної дає `E_UNDEFINED`, а не нуль. В `S²(or, b1, b2)` обчислюються обидва аргументи: це строга суперпозиція з посібника, а не скорочене обчислення Python `or`. В `IF` обчислюється тільки обрана гілка.

`Result.state` — кінцевий стан лише за `status=finished`. За помилки це останній досягнутий проміжний стан; він не є значенням часткової семантичної функції.

## Межі реалізації

За замовчуванням ліміт — 10000 відвідувань обчислювальних вузлів. У AST-інтерпретаторі рахуються входи в оператори, арифметичні та логічні вузли; кожна повторна перевірка циклу і кожне виконання тіла рахуються знову. У семантичному обчислювачі рахуються застосування термів. Блоки усуваються при побудові терму, тому числа кроків двох обчислювачів можуть відрізнятися. Семантична еквівалентність порівнюється за результатом, а не за кількістю кроків.

Текст обмежений 100000 символів, літерал — 1000 цифр, модуль цілого значення — 8192 бітами. Вкладеність обмежена стеком Python; її вичерпання явно діагностується. `resource_exceeded` та `limit_exceeded` — обмеження інструмента, а не математичне доведення невизначеності програми. Точна кількість допустимих рівнів вкладеності залежить від середовища Python.

Трасування зберігається в пам’яті, тому для великих обчислень бажано `run` без trace. Машинні SourceSpan відраховують Unicode-символи Python, а не байти чи UTF-16 одиниці. Початок діапазону включено, кінець виключено; рядки та колонки починаються з 1. Для IDE з UTF-16 потрібне перетворення позицій.
